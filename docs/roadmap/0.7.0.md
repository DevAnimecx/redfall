# 0.7.0 — The detector suite

> **Outcome, measured 2026-11-02.**
> **Tuned corpus (`pythonbank`): 100% — 17 of 17.**
> **Holdout corpus (`vulnbank`): 18.8% — 6 of 32.**
>
> The gap between those two numbers is the honest result of this phase, and it
> is the reason the holdout was built before any detector was written. The 100%
> is substantially **memorisation**: the detectors were shaped against
> `pythonbank`'s exact code. The number that counts is the holdout, and it says
> this work is roughly a quarter done, not finished.

This plan exists because the current recall is a failing grade, and because the
first thing to do about a failing grade is find out *why* it is failing rather
than adding more of what is already there.

---

## 1. The diagnosis, measured

Every number below comes from running the engine against `pythonbank` and
reading what it produced. Nothing here is estimated.

### 1.0 What actually happened

Three things, in order:

1. **The diagnosis held.** Nine of the eleven original misses did need new
   detectors, and the five modules in §2 Phase 0.7.3 now cover all nine classes.
2. **The tuned corpus went to 100%.** Every one of `pythonbank`'s 17 seeded
   flows is now reported, with the two remaining taint gaps (`open_redirect`,
   `ssrf_metadata`) closed by a redirect sink and an unrestricted-fetch rule.
3. **The holdout exposed the result as partial.** `vulnbank` — TypeScript, a
   different codebase, never opened while the detectors were written — scores
   **18.8%**. Detectors fire there (14 candidates on 21 files) but land on the
   wrong lines and cover classes this pass did not write detectors for:
   `xss_stored`, `prototype_pollution`, `mass_assignment`, the `jwt_*` family.

**The lesson is the plan's own premise, confirmed.** A tuned corpus will reach
any number you aim it at. Without the holdout split, this phase would have
shipped "100% recall" and been wrong by a factor of five.

### 1.1 Correction: the 29.4% was partly a measurement bug

The original baseline was **too low**. The recall scorer's sink→category map
tested for the substring `"exec"`, which matches `cursor.execute` but **not**
`subprocess.run`. So the engine found a real command-injection bug at
`tools.py:24` and the scorer filed it as a miss.

Fixed, re-measured: **35.3%** (6/17). Seven invented, down from eight.

The lesson is not "the number was wrong" — it is that **a harness that
under-counts is as dishonest as one that over-counts**, and this one was
under-counting. `bench/BASELINE.md` carries the correction.

### 1.2 What the 11 remaining misses actually are

Not one problem. Three different ones, requiring three different fixes.

| Group | Count | What it needs |
| --- | --- | --- |
| **A. Genuine taint-shaped misses** | 1 | A sink-table entry |
| **B. Found but mislabelled** | 1 | A category that distinguishes the variant |
| **C. Not taint flows at all** | 9 | Nine detectors that do not exist |

**Group A — genuine engine gap (1 flow).**
`open_redirect`: the engine reports **0 sinks and 0 taint paths** for
`redirect.py`. `classify_call` in `symbols_py.py` has no rule for `redirect`,
`abort`, `url_for` or `make_response` — the Flask response-construction family.
This is a one-line table addition plus a rule.

**Group B — found but mislabelled (1 flow).**
`ssrf_metadata`: the engine **does** find `requests.get` at `proxy.py:18`. The
corpus seeds `ssrf_metadata` (SSRF against the link-local range) as a distinct
class from `ssrf`; the engine reports the sink kind and cannot tell them apart.
Half of this is a real gap — nothing inspects the *argument* for a
metadata-range literal — and half is a corpus modelling question. Both are
addressed below.

**Group C — nine flows taint analysis cannot reach (9 flows).**
This is the bulk of the gap and **no amount of taint depth moves any of it**.
Each needs a detector of a different shape:

| Missed | Detector shape | Signal |
| --- | --- | --- |
| `hardcoded_secret` | Literal scan | A high-entropy literal assigned to a secret-named symbol |
| `secret_exposure` | Route × literal | A secret-named symbol returned by a handler |
| `weak_password_hash_md5` | API misuse | `hashlib.md5` reachable from a password path |
| `missing_rate_limit` | Route absence | A mutating route with no limiter in its decorator chain |
| `verbose_error` | Response shape | A handler returning a traceback or exception string |
| `user_enumeration` | Behavioural diff | Two auth branches with distinguishable responses |
| `csv_injection` | Output encoding | A CSV writer fed an unescaped request value |
| `unrestricted_file_type` | Input check absence | An upload handler with no extension/content allowlist |
| `idor` | Route × auth | A parameterised route with no ownership check |

**The headline finding of this diagnosis:** 9 of 11 misses need entirely new
detectors. A deeper taint engine would take recall from 35% to about 41% and
then stop. The CVE-shaped work in this plan is the nine.

## 2. The plan

Four phases. Each closes a named group from §1.2, and each ends with a measured
recall number rather than a feature list.

### Phase 0.7.1 — Make the measurement trustworthy first

Before adding a single detector, the instrument must be one you can believe.

- **Property-test the scorer.** A scorer that under-counted once can
  under-count again. New tests: every sink name the engine can emit must map to
  a corpus category or explicitly to `unknown`; a mapping table with gaps fails
  the build. This is the test whose absence let `subprocess.run` slip through.
- **Split the corpus: tune vs. holdout.** `pythonbank` becomes the *tuned*
  corpus. A second corpus is generated from the other range targets and
  **never inspected while building detectors**. The tuned number is reported
  alongside the holdout number, and only the holdout one counts as evidence.
  Without this, 99% on a 17-flow corpus you tuned against is worth nothing.
- **State recall per category, always.** A single aggregate lets nine
  detectors at 100% hide one class at zero.

**Done when:** the scorer has property tests, and a fresh recall run reports
both `tuned` and `holdout` numbers.

### Phase 0.7.2 — Close the taint gap (groups A and B)

Small, concrete, and it drains the "taint-shaped miss" list to zero.

- **Response-construction sinks.** Add the Flask/Starlette redirect family to
  `classify_call`, as a `redirect` sink kind. Fixes `open_redirect`.
- **Argument-aware SSRF classification.** When an SSRF sink's argument is a
  literal in the link-local, loopback or private range — or a request value
  concatenated with one — classify `ssrf_metadata` rather than `ssrf`. Fixes
  the labelling half of `ssrf_metadata`.
- **Corpus modelling decision, stated.** If the corpus keeps `ssrf_metadata`
  as a distinct class, the engine must report the distinction; if it does not,
  the corpus entry is wrong. Decide it explicitly in the changelog rather than
  leaving the mismatch to be discovered by a failing number.

**Done when:** `open_redirect` and `ssrf_metadata` both report as found, and a
test pins each classification.

### Phase 0.7.3 — The nine detectors (the real work)

A new module per detector family, each with the same shape: a function over the
parsed graph returning candidate findings, a proof contract, and range coverage.
They are **not** taint — they read the graph, routes and literals directly.

| Module | Detects | Method |
| --- | --- | --- |
| `detect/secrets.py` | `hardcoded_secret`, `secret_exposure` | Entropy + naming over literals; handler-reachability for exposure |
| `detect/crypto.py` | `weak_password_hash_md5`, `missing_signature_verify` | Weak-primitive reachability from a password/signature path |
| `detect/route_posture.py` | `missing_rate_limit`, `idor`, `unrestricted_file_type`, `missing_csp` | Route × decorator-chain × parameter inspection — the "absence" family |
| `detect/response.py` | `verbose_error`, `user_enumeration` | Response-shape and branch-divergence analysis |
| `detect/encoding.py` | `csv_injection`, `open_redirect` (confirm) | Output-encoding checks at write sites |

**Why these are modules and not taint rules.** `missing_rate_limit` is an
*absence* — there is no flow to trace, only a route with no limiter. `idor` is
an authorisation absence. `verbose_error` is a response property. Forcing them
into the taint engine would produce findings that cannot be reproduced, which
is the exact failure this project exists to prevent.

**Each detector must ship with its own range flow**, because a detector that
finds a bug it cannot reproduce has not found a bug. That is the rule the
language engines already follow.

**Done when:** each of the nine has a detector, a range flow it fires on, and a
test asserting it does **not** fire on the safe sibling route.

### Phase 0.7.4 — Reach the number, and prove it isn't gamed

- Run the full suite against the **tuned** corpus until recall is ≥99%.
- Run against the **holdout** corpus, which was never inspected during
  development, and report that number. **If the holdout number is materially
  lower than the tuned one, that is the finding** — it means memorisation, and
  it goes in the changelog rather than being smoothed away.
- Raise the committed baseline only to the *holdout* number.

**Done when:** holdout recall is measured and published, and the regression
gate enforces it.

## 3. Why 99% is achievable here, and what it does not mean

**It is achievable** because the corpus is 17 flows with known locations, and
every one of the nine missing classes has a well-understood static signature.
Literal scanners, route-posture checks and response-shape analysis are
engineering, not research. There is no reason a focused effort cannot find all
17.

**What it does not mean** — stated plainly because the number invites
misreading:

- **99% on `pythonbank` is not 99% on a real codebase.** A real application has
  flows the corpus does not seed, and this figure says nothing about those.
- **It is not a comparison.** Semgrep is not run on the same corpus. A 99%
  that nothing is measured against is a self-report.
- **Detectors have their own false-positive rate**, which the invented-rate
  metric tracks. Recall rising while precision collapses is not progress, and
  the bench reports both for that reason.
- **The anti-gaming guard is load-bearing.** Without the holdout split in
  Phase 0.7.1, "99%" would mean "we tuned 17 detectors to 17 known bugs."

---

## 4. What 0.7.0 refuses to do

- **Refuse to raise recall by widening what counts as a match.** The matcher
  stays as strict as the range runner's; a looser matcher would make the number
  rise while the engine gets no better, which is the cheapest possible fraud.
- **Refuse to add a detector without a range flow it reproduces on.**
- **Refuse to report a tuned number as the result.** Both numbers, always.
- **Refuse to let one category hide behind the aggregate.** Per-category recall
  is on every report.

## 5. The order to do it in

```
0.7.1 scorer property tests + holdout split   ← blocks everything; a number
      │                                          you cannot trust is worse
      │                                          than no number
      ▼
0.7.2 taint gap (2 flows)                     ← days, drains the A/B groups
      │
      ▼
0.7.3 nine detectors                          ← the bulk; one module per family
      │                                          secrets → crypto → route
      │                                          posture → response → encoding
      ▼
0.7.4 measure both corpora, publish both      ← 99% tuned, holdout reported,
                                                 baseline set from holdout
```

**Phase 0.7.1 is not optional and not parallelisable with the rest.** Adding
detectors against a scorer that has already under-counted once is how the next
29.4% gets published as a fact.
